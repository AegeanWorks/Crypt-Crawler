# Decisions

Why this project is built the way it is, oldest first. One entry per decision that changes a
contract, a dependency, a data format or the architecture; IDs are consecutive and never reused.

### ADR-001: Architecture of Crypt-Crawler Web Game and Visual Inspection Suite
- **Date**: 2026-10-24
- **Status**: Accepted
- **Context**: Need a responsive, tactical web-based dungeon crawler with high UI fidelity and automated visual verification capability using headless browser technology.
- **Decision**: Adopt a zero-external-dependency Python runtime (`http.server` with custom JSON dispatch) paired with a modern Vanilla ES6 Canvas + CSS3 frontend. For automated visual verification and UI auditing, provide a Playwright-driven headless Edge inspection harness (`tools/inspect_ui.py`) and standard unittest suite (`tests/`).
- **Consequences**: Zero frontend compile/bundle step enables instant live-reloading and cold starts; headless Edge runs natively on Windows without requiring separate browser binary downloads; unit tests and visual screenshots provide comprehensive coverage.

### ADR-002: One-Click Launchers and Seamless Floor Descent State Persistence
- **Date**: 2026-10-24
- **Status**: Accepted
- **Context**: Users need immediate zero-friction launching with automated browser opening; furthermore, descending dungeon stairs must preserve character level, equipment, and backpack inventory.
- **Decision**: Provide `PLAY.bat` and `play.sh` with automatic Python detection and `--open` browser integration. In `engine.js`, implement `descendFloor()` to regenerate the deeper dungeon while preserving all player progression attributes.
- **Consequences**: Players can start playing with a single click, and RPG progression smoothly persists across dungeon depths.

### ADR-006: Relic Slots, Equipment Comparison Diffs and Procedural Visual Feedback
- **Date**: 2026-10-25
- **Status**: Accepted
- **Context**: Inventory decisions lacked depth: no amulet or boots slots, no side-by-side comparison, limited relic variety, and combat rewards gave little visual confirmation.
- **Decision**: Add backward-compatible `amulet` and `boots` equipment slots to the Python and client models, with save loading defaulting missing keys to `null`. ### ADR-007: Correct Inventory Selection, Equipment Caps and Trustworthy Inspection Gate
- **Date**: 2026-10-25
- **Status**: Accepted
- **Context**: Reviewing the CC-006 commits found the sorted inventory highlighted a slot by grid position instead of the item's true inventory index, stat comparisons labelled proc chances without a percent sign, and the offline merchant fallback omitted the new relics. The headless inspector also reported every recorded check as passed and exited 0 even when a boolean check was false, hiding exactly this class of regression. Separately, +Max HP/MP relics could leave current HP or mana above their cap after unequip, and Python healing capped at the unequipped maximum.
- **Decision**: Track each rendered slot's original inventory index in `data-index` and highlight by that index. Show percentage suffixes and an explicit no-change state in the comparison card. Mirror the six new relics in the offline merchant fallback. Make `tools/inspect_ui.py` count only true audit checks, list failures, and exit 1 when any check fails. Clamp HP and mana to the equipment-granted caps on equip/unequip in both engines, and make Python healing and mana restoration use the effective maxima.
- **Consequences**: Selection feedback stays correct under filtering and rarity sorting; the inspector now blocks silent regressions; current pools can never exceed the caps of the gear actually worn; all behavior remains backwards compatible with existing saves.

### ADR-008: Single-Scroll Mobile Layout Below 768px
- **Date**: 2026-10-25
- **Status**: Accepted
- **Context**: A visual review of the shipped build showed the phone layout was unusable. Below 768px the shell and `.game-main` stayed viewport-bound, so `.panel-viewport` compressed to 288px while its canvas, 7-button action deck and D-pad needed about 554px; because that panel also had `overflow: hidden`, only the top 12px of the deck was painted and the D-pad was entirely invisible. Panel flex-shrinking pushed the character panel over the clipped deck, the header's Guide and New Game buttons overran the right edge by 154px (document scrollWidth 544 at a 390px viewport), and the backpack was sealed inside a second nested scroll context.
- **Decision**: Below 768px treat the page as one scrolling document: the shell loses its height clamp and `overflow`, `.game-main` becomes a non-shrinking flex column with visible overflow, and every `.panel` keeps its content height (`flex: 0 0 auto`) while `.panel-viewport` stops clipping. The header action group wraps and its buttons shrink slightly. `tools/inspect_ui.py` now asserts, per viewport, that no horizontal scroll exists, the last action-deck button stays inside the viewport panel, the D-pad is shown only at narrow widths and stays inside that panel, and the inventory panel is reachable within the document height.
- **Consequences**: Mobile players can reach every action, the D-pad and the full backpack through one vertical scroll; desktop and laptop layouts are untouched because every change is scoped to the 768px breakpoint; the layout audit fails the build if any of these regressions return.

### ADR-009: Lore Codex, Lost Souls, Sigil Vaults and Boss Phases
- **Date**: 2026-10-25
- **Status**: Accepted
- **Context**: Combat and loot were solid but the run had no narrative payoff and little non-combat interaction: story existed only as one-line log text, discoveries were not recorded anywhere, every floor played the same way, and the final boss was a single stat check. Reviewing the save path also showed prop state was not persisted, so resuming a run resurrected opened chests, untriggered traps and unbroken urns.
- **Decision**: Add a data-only lore codex in `crawler/lore.py` served by `/api/lore`, with a Journal panel that shows discovered entries and hides the rest; discoveries are recorded in `localStorage` (`crypt_crawler_lore_v1`) so they survive death. Add one Lost Soul per floor, a dialogue with three meaningfully different choices (ember healing, penitent gold/relic, story plus XP). Add three floor sigils and a sealed vault that pays a legendary relic, gold, XP and lore, tracked by a header pill and a bounty. Give Malakor two phases (50% summons two skeletons and raises attack; 25% enrages) and show champion affixes and status durations in the hover tooltip. Persist every prop's spent state in the save and parse both legacy coordinate arrays and the new objects. Block keyboard and canvas input while a modal is open.
- **Consequences**: Exploration and lore now carry across runs, floors have an optional goal with a real reward, the final fight changes shape, hover inspection is informative, and a resumed run cannot farm the same chests again. All new save fields default safely for older saves, `/api/lore` is additive, and the headless audit asserts journal, dialogue, prop round-trip, vault payout and both boss phases.
- Cross-principle check: no principle section changed. Serves PRINCIPLE-001 (one data path), PRINCIPLE-003 (additive contract, tested), PRINCIPLE-005 (README updated), PRINCIPLE-014 (failing-first tests for lore and generation) and PRINCIPLE-015 (live browser dogfooding).

### ADR-010: Props Are Reserved Tiles; Offline Parity and Immediate Level-Ups
- **Date**: 2026-10-25
- **Status**: Accepted
- **Context**: Reviewing CC-009 found monsters could cover interactive props. Random spawns ignored chests, shrines and urns, and the depth-3 boss escorts ignored every prop: seed 999 placed an escort skeleton on a sigil. The browser-side movement and summon checks had the same gap, so a Risen Skeleton could be raised onto a sigil or the vault. The offline fallback dungeon also had no Lost Soul, sigils or vault, so the new objective vanished whenever `/api/new-game` was unavailable. Separately, bounty and kill-streak bonuses added XP directly instead of through `_grantXp`, deferring level-ups that should fire immediately, and `resolveSoul` consumed a soul even for an unknown choice.
- **Decision**: Build one `reserved` set of every interactive prop plus spawn and stairs on the server, and use it for both random spawns and the two boss escorts. Mirror the rule in the client `_isOccupied` so monsters never move or get summoned onto merchants, chests, shrines, urns, souls, sigils or the vault. Give the offline fallback one soul, three sigils and a vault on walkable room tiles, and move its fixed spider off the shrine. Validate the soul choice before marking the soul resolved. Route bounty, double-slay and rampage XP through `_grantXp` so a level-up is immediate and identical in every source.
- **Consequences**: Every interactive prop stays visible and reachable, and the floor objective and boss phases work identically online, offline and in the browser. Level-ups no longer lag behind bounty payouts. Spawn placement now reserves more cells, which can reduce monster count by at most the number of props in a room. The headless audit asserts offline souls/sigils/vault, prop occupancy, and the server test sweeps seeds and depths for prop coverage.
- Cross-principle check: no principle section changed. Serves PRINCIPLE-003 (platform parity between server and client), PRINCIPLE-014 (regression test for spawn coverage) and PRINCIPLE-015 (live offline-path dogfooding).

### ADR-011: Black Pact Altars, Deck Hotkey Priority and Descent Guard
- **Date**: 2026-10-29
- **Status**: Accepted
- **Context**: The run still had no repeatable risk-for-power decision: shrines and souls only give upside or a safe pick, so a strong build never has to trade anything away. Reviewing the input path also found a real usability defect: movement used the number row `2`, `4` and `6`, while the same keys are advertised as the Fireball/Bash/Heal/Potion deck hotkeys, so the first matching `switch` case won and `[2]`, `[4]` and `[6]` silently moved instead of casting. Descending floors was also re-entrant: the `async` fetch left input live, so a second step on the stairs could increment depth twice and fetch two maps.
- **Decision**: Add one Black Altar per floor (`TileType.PACT`) with three exclusive bargains: Pact of Wrath (+4 permanent ATK, burns 20% of max HP), Pact of the Grave (+18 max HP and healing, seals 3 max mana) and Pact of Avarice (120 + 30Ã—depth gold, raises two Pact-Bound Wraiths). The altar is generated before sigils so no objective consumes its tile, is reserved against monster spawns and movement in both engines, persists its `used` flag in saves, unlocks the new `lore_pact` entry and has a dedicated renderer, minimap marker and modal. Read numpad movement from `e.code` so the number-row deck hotkeys keep their advertised behavior, and guard `descendFloor` and `stepPlayer` with a `transitioning` flag.
- **Consequences**: Every floor now presents a build-defining choice with an explicit cost, the deck hotkeys match their labels, and a held movement key cannot skip a floor. Existing saves without `pacts` load as an empty list, the server and offline fallback both carry one altar, and the headless audit asserts the three choices, the applied cost/boon, invalid-choice rejection, lore unlock and save round-trip.
- Cross-principle check: no principle section changed. Serves PRINCIPLE-003 (server/client parity), PRINCIPLE-014 (generation, server and lore tests) and PRINCIPLE-015 (live browser audit of the bargain modal).

### ADR-012: AI-Playable Mechanics Harness, UI Guard Contract and Stat-Base Parity
- **Date**: 2026-10-29
- **Status**: Accepted
- **Context**: Mechanics lived only in `static/js/engine.js`, so an agent could inspect screenshots but could not read state, play a turn or assert a rule, and any Python re-implementation would drift from the shipped game. The project also had no `.aikit/ui.json`, so the opt-in UI guard could not bound a UI edit, and the first harness run exposed a real parity defect: the client `_recalculatePlayerStats` used a 60 HP / 3 DEF paladin base while `HERO_CLASSES` ships 65 HP / 4 DEF, so the first turn silently rewrote a fresh paladin's stats.
- **Decision**: Add `tools/ai_harness.py`, a stdlib CLI that drives the shipped engine in headless Edge and prints JSON. `catalog` exposes the data contract; `play` installs a mulberry32 `Math.random` seeded from `--seed`, starts the engine at an explicit seed/depth/class, validates every action, and prints each step plus the final state and `layout_hash`; `selftest` proves determinism, per-class deck labels, all three pact bargains surviving turns, boss damage and save round-trip. Add `tools/ui_inventory.py`, a deterministic inventory of controls, choices, handler groups and theme tokens, and `.aikit/ui.json` binding the `game-ui` surface (`static/**`) to that inventory and the unit suite, with `static/css/style.css` and `static/js/renderer.js` as theme paths. Correct the client base stats to mirror `HERO_CLASSES`.
- **Consequences**: An agent can now read and drive the real game with reproducible results, and the UI guard can bound and verify UI edits without a browser. The harness needs Playwright+Edge for `play`/`selftest` only; `catalog`, the inventory and the 12 new unit tests stay stdlib-fast. The stat parity fix raises a fresh paladin from 60/3 to the documented 65/4, and existing saves are clamped to the corrected caps. The project already carries `ui_required: true`, so delivery needs one finished UI task (`ui begin`, `ui verify`, `ui finish --reviewed`) recorded against the committed surface.
- Cross-principle check: no principle section changed. Serves PRINCIPLE-003 (the harness tests the shipped engine, not a copy), PRINCIPLE-010 (bounded JSON commands), PRINCIPLE-014 (validation, inventory and determinism tests) and PRINCIPLE-015 (dogfoodable agent entrypoint).

### ADR-013: Descent Lifecycle Hardening and Non-Vacuous Audit Checks
- **Date**: 2026-10-29
- **Status**: Accepted
- **Context**: An independent review of the pact-altar change found the async-descent guard was incomplete. `descendFloor` cleared `transitioning` only on the success path, so any exception after the inner try left movement softlocked until reload; `start()` neither reset the flag nor invalidated a pending descent, so pressing New Game mid-descent let the old fetch replace the fresh run's dungeon and rewrite its player position. The flag also guarded movement only: deck hotkeys, potion, wait, inventory use and canvas clicks still drove turns on the old map after `depth` had advanced. Two new inspector checks were also vacuous: the render check asserted only FOV visibility (it passed with `_drawPact` deleted, and passed with `skip` when no altar existed), and the save check used `[].every(...)`, which is true for an empty pact list. Finally, nothing tested the two advertised input/descent fixes, a degenerate 20Ã—20 map could ship no altar, number-row 7/8/9 diagonals were dropped, and a death after a pact modal kept the "Refuse the bargain" close label.
- **Decision**: Bump a `runToken` and reset `transitioning` in `start()`, capture the token in `descendFloor`, bail after each `await` when it changed, assign `depth` only after the map arrives, and clear the flag in a `finally` guarded by the token. Gate every turn entry point (`keydown`, `_handleCanvasClick`, `triggerSlotAction`, `quickPotion`, `waitTurn`, `useInventoryItem`) on `transitioning`. Make the inspector render check require exactly one altar and count real `_drawPact` invocations during a render, and make the save check require a non-empty pact list with matching coordinates. Add failing-first harness checks for number-row-vs-numpad routing, single-flight descent, flag clearing and new-run precedence, plus a dungeon test for degenerate maps and a fallback altar placement. Restore number-row 7/8/9 diagonals and reset the modal close label on death and victory.
- **Consequences**: A descent can no longer corrupt a new run, stick the movement lock or advance the depth twice, and a slow response cannot let a turn resolve on the old floor. The inspector can now fail when the altar renderer or save field disappears. The altar contract holds on every generated map. The four new harness checks need Playwright and run in `selftest`; the dungeon test stays stdlib.
- Cross-principle check: no principle section changed. Serves PRINCIPLE-003 (state and platform parity), PRINCIPLE-013 (recoverable state, no stuck flag), PRINCIPLE-014 (failing-first tests for each fix) and PRINCIPLE-018 (honest gates).

### ADR-014: Spawn Uniqueness, Stairs Boss Guard, Wraith Sprite and Prop Tooltips
- **Date**: 2026-10-29
- **Status**: Accepted
- **Context**: Verifying the pact work with a seeded fuzz run over three classes and five seeds found two pre-existing generator defects: the per-monster random roll ignored already placed monsters, so 325 of 900 sampled floors stacked two enemies on one tile (two skeletons, or a bat and a skeleton, occupying the same square and sharing one collision target), and the Depth-3 boss used `rooms[-1]`, which is not the farthest room, so the lich could stand on a chest, urn, sigil or the stairs (25 of 120 sampled Depth-3 floors overlapped a prop). Avarice also raised a `wraith` that had no renderer branch and fell back to a grey placeholder, and nothing told the player what an altar, soul, sigil or vault does before stepping onto it.
- **Decision**: Track an `occupied` set while spawning and reject duplicates; place the boss on `stairs_pos`, which the generator guarantees is clear and farthest, keep its escorts off reserved tiles, and skip the boss room by identity. Add a crimson wraith sprite (drifting shroud, bone mask, red eye points, hanging chains) with a bestiary entry. Add `renderer._propAt` plus a world-space hover card for the altar, soul, sigil and vault, and extend the in-game guide to cover pacts, souls, sigils, the journal and the number-row/numpad split. Extend the harness with wraith killability, pact-bonus survival across level-up and equip/unequip, page-error capture (a run with a page error now fails), and extend the inspector with pixel-diff proofs for the altar render and the tooltip card plus a wraith render check.
- **Consequences**: No floor ships two monsters on one tile or a boss on a prop, the Depth-3 fight happens at the stairs as designed, Avarice's debt is a legible, killable enemy, and every interactive prop explains itself on hover. The audit is stricter: renderer and tooltip checks now compare canvas pixels, so deleting a draw path fails the gate instead of passing on a state check. `play` exits non-zero when the page logs an error.
- Cross-principle check: no principle section changed. Serves PRINCIPLE-003 (server/client parity and read-before-write), PRINCIPLE-014 (dungeon and server tests for both defects) and PRINCIPLE-015 (pixel-level UI proof).

### ADR-015: Shell-Safe Harness Inputs, Rejected-Action Reporting and Resume Coverage
- **Date**: 2026-10-29
- **Status**: Accepted
- **Context**: Reviewing the last three commits found the documented harness command was unusable in this repo's own shell: PowerShell and `cmd` strip the inner double quotes of a native argument, so `--actions '[{"action":"wait"}]'` reached the parser as `[{action:wait}]` and failed with a bare JSON error. A rejected action also crashed `play` with a traceback and no JSON reply, `teleport` accepted a wall tile and produced states with the player outside the map, and the save test proved only the raw fields â€” the resume path that rebuilds the run was untested.
- **Decision**: Accept `--actions @file` alongside inline JSON, and turn a JSON parse failure into a message that names the shell quoting and both file forms. `play` now catches a rejected action, records `steps[].error` plus a top-level `failure`, and exits 1 with a complete JSON reply. `teleport` refuses a non-walkable target in the engine bridge. Add a selftest check that saves after a pact, resumes through `start(..., allowResume)`, and asserts attack, max HP, the pact bonus field, the spent altar and the cleared transition flag all survive.
- **Consequences**: The documented command works on Windows shells, a failed action is a machine-readable result instead of a traceback, the debug pose cannot manufacture impossible states, and resume â€” a distinct code path from a fresh start â€” is covered. `catalog` now advertises the input forms so an agent does not have to read the source.
- Cross-principle check: no principle section changed. Serves PRINCIPLE-010 (bounded CLI I/O), PRINCIPLE-011 (actionable errors) and PRINCIPLE-014 (resume regression coverage).

### ADR-017: Complete Seeded Layout Fingerprint and Scroll Coverage

### ADR-019: Two-Way Merchant and Rarity-Based Selling
- **Date**: 2026-10-30
- **Status**: Accepted
- **Context**: Hermit Grimbold could only sell to the player. Outclassed loot filled the 12-slot backpack and could only be dropped, so gold had no outlet after the main upgrades and unwanted gear had no value. The merchant modal was also a single long list, which left no room for a second action without adding an undiscoverable section below the stock.
- **Decision**: Give the merchant modal **Buy** and **Sell** tabs. The Sell pane lists every backpack item with a rarity-based price (common 10, rare 30, epic 60, legendary 100), and `sellInventoryItem` refuses to run unless `UIController.shopOpen` is true, so the rule cannot be triggered from a closed modal. A sale removes the item, adds gold, clears any inventory selection, saves the run, and reopens the modal on the Sell tab so several items can be sold in a row. Buying keeps the existing stock flow and reopens on the Buy tab.
- **Consequences**: The economy now has both a source and a sink: players can clear a full backpack without discarding value, and the price table keeps selling below the merchant's buy prices. No save field changes because gold and inventory already persist. The harness proves a real Sell-tab click (gold up, inventory down, tab preserved, closed-shop call refused), and the inspector adds the same sale to the shop scenario.

### ADR-058: Execute feedback is rogue-only and includes the bonus (improvement cycle 17)
- **Date**: 2026-11-08
- **Status**: Accepted
- **Context**: The map skull marker and the hover card's "EXECUTE 💀" suffix were drawn for every class whenever a monster was at or below 30% HP, although only the rogue's Executioner passive grants +25% damage there. The hover strike range also ignored the multiplier, so a rogue's preview read ~5-8 while the actual execute hit could reach ~10. The paladin/mage saw a promise the engine did not keep; the rogue saw an underestimate.
- **Decision**: Pass `player.hero_class` into `_drawMonster` and draw the skull only for `heroClass === "rogue"`; in `_drawMonsterTooltip`, compute `execute = player.hero_class === "rogue" && hp <= 30%`, apply `mult = 1.25` to the preview range, and append "EXECUTE" only then. Add `tests/test_execute_marker.py` for the class gate and the multiplier; the engine's existing `rogue_executioner_boosts_low_hp_targets` selftest remains the damage contract. Observed but out of scope: the champion title and right-aligned affix overlap on long names ("Swift Crypt SkeletonSWIFT"), which belongs to a UI readability cycle.
- **Consequences**: Only the rogue sees the execute window and its boosted preview; other classes see the plain strike range. 167 unit tests green, harness 93/93, inspector 75/75 at three viewports with 0 console errors, `aikit check` 5/5. Evidence: seed 42 B1F, 60/200 HP target: paladin before "EXECUTE" + skull, after neither; rogue before "~5-8 EXECUTE", after "~7-10 EXECUTE" with the skull retained.
- Cross-principle check: no principle section changed. Serves PRINCIPLE-003 (read-before-write), PRINCIPLE-014 (failing-first marker test), PRINCIPLE-009 (renderer consumes the existing hero class, no new state).

### ADR-059: Boss phases belong to their own boss (improvement cycle 18)
- **Date**: 2026-11-08
- **Status**: Accepted
- **Context**: The 50% and 25% boss phase blocks were keyed on `monster.is_boss`, not the boss type. Every boss therefore ran Malakor's phase first: the Hollow Choir's `phase_two` was consumed by "Malakor tears open the vault floor" and two risen skeletons, so its own split never ran (seed 42 B2F: 0 echoes, 3 skeletons, wrong log). The foundry Ashen Warden borrowed the same Malakor text and summoned two skeletons (5 total). The Choir's split also failed when its four neighbours were crowded, and still logged "splits into 0".
- **Decision**: Type-gate Malakor's summon and enrage blocks with `monster.type === "boss_lich"`; give other bosses (excluding the Choir, which owns its phases) a named "seal breaks"/"fury" escalation at 50%/25%; let the Choir's split search rings 1-3 and, if still crowded, log "no room to split" without consuming `phase_two` so it retries. Add `tests/test_boss_phases.py` and the selftest checks `choir_split_finds_room_beyond_crowded_neighbours`, `pack_boss_keeps_its_own_phase`, `malakor_keeps_his_own_phases`.
- **Consequences**: The Choir splits into 2 echoes even beside the vault/warden (ring-2 tiles), the Ashen Warden escalates under its own name with no summons, and Malakor keeps his 2-skeleton summon and enrage. 170 unit tests green, harness 99/99, inspector 75/75 at three viewports with 0 console errors, `aikit check` 5/5. Evidence: seed 42 B2F Choir: before 0 echoes + 2 risen skeletons + "Malakor" log; after 2 echoes + split log. Seed 42 B3F Ashen Warden: before 5 skeletons + Malakor log; after 3 skeletons + "Ashen Warden's seal breaks" and attack 15 -> 18.
- Cross-principle check: no principle section changed. Serves PRINCIPLE-003 (read-before-write), PRINCIPLE-014 (failing-first phase checks), PRINCIPLE-009 (each boss owns its phase block; no new subsystem).
